## Active v3 schema

```json
{
  "version": 3, "currency": "VND", "name": "Synthetic example", "demo": false,
  "startMonth": "2026-11", "endMonth": "2027-12",
  "objects": [{"id": "family", "name": "Synthetic family", "type": "group"}],
  "items": [{
    "id": "expense", "objectId": "family", "type": "expense", "status": "confirmed",
    "name": "Synthetic expense", "description": "", "amount": 2000,
    "recurrence": {"kind": "interval", "anchor": "2026-11", "end": "2027-12", "everyMonths": 1},
    "amountChanges": [{"month": "2027-01", "amount": null}]
  }],
  "accounts": [], "snapshots": [], "debtAccounts": [], "debtSnapshots": []
}
```

- Cash account: `{id,name}`. Debt account: `{id,name,direction:"payable"|"receivable"}`. Snapshot in its corresponding list: `{id,accountId,date:"YYYY-MM-DD",amount:integerVND}`.
- IDs are globally unique strings ≤80 characters, values not prototype keys. Objects/types do not create login identities. Object/account names ≤80, detail names ≤100, descriptions ≤500. No implicit name merging. One object owns each detail; no split/membership model.
- ≤500 details, ≤500 objects, ≤500 accounts per list, ≤5,000 snapshots per list, ≤120 change points/detail; the 1 MB bound may constrain these further. Strict active-schema fields reject unsupported data, including actual maps, rather than silently dropping it.
- Money: `null` (plans only) or exact integer 0–1,000,000,000,000. Monthly, cumulative income/expense, cash and debt arithmetic must remain safe integers even when opposing flows cancel. Negative projected cash is valid.
- Window: 1–120 consecutive forecast months, 2000–2100. **Subsequent confirmed usage change:** full schedules are saved independently, within 2000–2100, and may span more than120 months. Only occurrences intersecting the window affect its forecast; changing the window preserves all schedules and estimate history rather than blocking or truncating out-of-window occurrences. This supersedes r002's window-exclusion rejection, not its data-preservation rule. Once uses anchor=end, interval=1. Monthly/yearly are intervals1/12; N is integer1–120. No automatic window/routine extension. Past/future details remain editable, using a real scheduled occurrence even when none falls in the window.
- Sorted unique estimate changes must be scheduled occurrence months. Changes replace at/after the chosen month until another point; earlier values and later points remain. Same-point replacement is previewed/confirmed. Whole-series schedule changes are separately confirmed and cannot orphan changes.
- Reference dates are real Gregorian dates, today/history only, using **Asia/Ho_Chi_Minh**. A same-account/date record must be corrected with confirmation, retaining its ID; never summed with another record that day. The UI does not expose destructive account/history deletion or debt-direction reassignment.

### Forecast semantics and worked example

Income/expense expansion covers only the chosen forecast window. For example, a synthetic yearly schedule October2027–October2037 saved alongside a November2026–December2027 window contributes only in October2027; the full2037 end remains saved, with no automatic horizon extension. Moving the window to2030 reveals its original October occurrence and any applicable saved estimate changes. Costs outside the window are not replayed into opening cash or reported as unknown amounts inside it.

For each month, choose each cash account's latest snapshot with reference month ≤ calculated month, independent of entry order. At the first month or any month with a new snapshot, reset the pooled opening to the sum of those account references, including stale dates in other accounts; absent references mean incomplete. Otherwise carry the prior closing. Apply the full month's included plans once. Snapshots are not income. A complete reset clears prior carried uncertainty; an unknown included plan makes closing incomplete again. No annual reset.

Synthetic VND: November A=3,000 + B=7,000 − expense2,000 → **8,000**. December only B refreshes6,000: stale A3,000+B6,000 opens9,000; −full2,000 → **7,000**. January without refresh opens7,000; −2,000 → **5,000**. The deterministic automated equivalent uses November2025–January2026 so it remains historical under the real clock. December's snapshot never changes November. This approximate reset may overlap real spending; it is deliberately not transaction reconciliation.

Debt totals separately select payable/receivable snapshots. Neither changes cash. An ordinary repayment expense1,000 reduces its month/carry1,000 exactly once; a collection income400 raises it400. Neither updates the outstanding debt. No inferred full-balance payment.

### Amount grammar

See the [README examples](../README.md#amounts-and-calculations). One parser is used for every amount control. Bare default ×1,000; M/tr/triệu ×1,000,000; k/ngàn/nghìn ×1,000; colloquial trăm ×100,000; VND/đ/đồng ×1. Consistent groups of three with comma or dot are grouping (including `1,000tr` = 1 billion); one/two decimal digits are allowed. Mixed grouping/decimal separators and unsupported precision reject. BigInt scaling/divisibility avoids floating rounding; stored JSON is integer VND. Editors format explicit literal VND so reopening cannot rescale.

## Storage / API

Private directory: `plan.json`, exclusive `writer.lock`, possible `.save-*` crash remnants, and `original-<sha256>.json` archives for explicitly converted legacy server envelopes. Archives are immutable **by application convention** (exclusive create/no overwrite and byte equality checks), not protection against an operator with filesystem permissions. Keep manual originals/exports separately; laptop disk is not backup.

Envelope: `{schemaVersion:"money-seasons-store/v1",revision:positiveSafeInteger,plan:v3}`. A missing initial file returns revision0/plan null; no automatic demo. Unsafe modes/symlinks/hard links, malformed/unsupported data, or missing data after initialization fail closed. Valid v1/v2 stored envelopes are returned unchanged with `migrationRequired:true`; normal writes are blocked until explicit migration.

Inside one queue: reread/validate → expectedRevision compare → validate candidate/totals → archive original if required → exclusive same-directory temporary0600 file → write/fsync → atomic rename → directory fsync → acknowledge next revision. Reads wait for pending writes. Post-rename failure sets `durabilityUncertain:true` and blocks writes until operator recovery/restart. Startup validates the store and syncs its directory. A lock is never stolen, including stale/unknown holders.

| Route | Behavior |
|---|---|
| POST `/api/login` | Allowed Host/Origin, bounded JSON/passphrase; sets session cookie, returns CSRF |
| GET `/api/session` | Authenticated in-memory session/CSRF |
| POST `/api/logout` | Auth/session/Origin/CSRF; invalidates session |
| GET `/api/plan` | Authenticated envelope/revision, optional legacy/uncertainty flag |
| PUT `/api/plan` | Auth/Origin/CSRF; ≤1,000,000 raw UTF-8 bytes; `{expectedRevision,plan,operation:"edit"|"replace",confirmed:true}`; legacy conversion additionally requires `migrationConfirmed:true` and confirmed replace |
| GET `/api/export` | Authenticated plan-only attachment; legacy originals still include actuals before conversion |

Errors:400 invalid/confirmation,401 login,403 boundary/CSRF,409 conflict,413 size,429 attempts,503 unavailable/uncertain. Responses never serialize exception text/paths/payloads. Static serving is allowlisted; finance responses no-store. No request-controlled filesystem paths.

Security: 12+ character secret, scrypt/unique salt, 256-bit random session/CSRF tokens, hashed session lookup, production Secure/HttpOnly/SameSite=Strict cookie; absolute24h sessions; logout/restart invalidation; ≤256 sessions. ≤5 failed/in-flight direct-client and30 global attempts/15min. Forwarded headers are not client identity; a proxy shares the client budget. Private HTTPS/ACL provisioning remains operator-owned. This is not multi-tenant authorization, personal attribution or an audited security certification.

## Legacy migration

Retain/download the complete original before conversion. Browser keys are never changed/deleted. Preserve original year-months, plan IDs, anchor/end and estimate changes. Each old detail gets a **separate** object from its person/category label; preview exposes names, short IDs and associated detail. Equal labels are not automatically merged; users can explicitly reassign details to a chosen shared object later. Original category/person text is retained in converted descriptions as well as the original.

Legacy actuals are retained in raw originals/exports/archives, not reinterpreted or counted in the active plans-only forecast. Opening cash is not converted into an invented dated account balance. The interface discloses both exclusions, requires an original download/ack and another replacement confirmation. A legacy server archive must be successfully created/fsynced before replacement; archive failure leaves the old plan intact. Real data migration is a separate operator action, never a test side effect.

## Operator recovery

**These procedures are reference, not authorization to change a running household instance.** Never commit private state, originals, exports, secrets or personal screenshots.

1. **Unsaved/conflict:** keep tab; close form, export unsaved candidate, read status. Exact candidate/no uncertainty reconciles a lost ack. Same revision permits explicit retry. Different revision requires export, explicit reload, manual reapply; no auto-merge. Form fields remain but must be reviewed against current data.
2. **Durability uncertainty:** disk can contain the complete new revision despite503. Export draft. Operator identifies/stops only the affected instance gracefully, preserves its entire directory, checks storage health and restarts with the same store. Startup validates/syncs; log in and reread before more edits. Never blindly retry or reset to sample.
3. **Stale `writer.lock`:** identify the exact directory/process/container and prove **no live or unknown writer** uses it; container PID namespaces make a PID alone insufficient. Preserve the directory. Only with separate authorization remove that exact stale lock/obsolete `.save-*` files and restart one writer. No broad kills/lock deletion or force takeover.
4. **Corrupt/unsafe file:** stop identified instance, preserve raw bytes privately. Correct modes/ownership without weakening privacy. Restore a verified complete envelope offline, or explicitly quarantine the corruption and start empty before confirmed plan import. Never treat an envelope as a plan or silently delete the old source.
5. **Legacy original:** byte archives contain the full old envelope, not a plan import. An operator may recover its `plan` to a separate private export or restore the full verified envelope offline. Never write over the running store or discard the archive.
6. **Disk loss:** only separately retained manual backup/export can help. No app encryption, automatic/off-machine backup or guaranteed recovery. Fault injection/SIGKILL checks complete old/new files, **not hardware power-loss guarantees**.
