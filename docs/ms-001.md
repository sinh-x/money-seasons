## V2 plan schema

Supported fields only; imported arbitrary metadata is dropped, never interpreted as cash or access configuration.

```json
{
  "version": 2,
  "currency": "VND",
  "name": "Synthetic example only",
  "demo": false,
  "startMonth": "2026-11",
  "endMonth": "2027-12",
  "openingCash": 100,
  "items": [{
    "id": "synthetic-expense",
    "name": "Synthetic expense",
    "type": "expense",
    "status": "confirmed",
    "category": "Sinh hoạt",
    "personLabel": "Gia đình",
    "amount": 10,
    "recurrence": { "kind": "interval", "anchor": "2026-11", "end": "2027-12", "everyMonths": 1 },
    "amountChanges": [{ "month": "2027-01", "amount": 20 }],
    "actuals": { "2026-12": 12, "2027-11": 0 }
  }]
}
```

- Plan name/ID ≤80, item name ≤100, category ≤40, personLabel ≤80 characters; ≤500 items and ≤120 change points/item.
- Amounts are `null` or exact integers 0–1,000,000,000,000; actuals cannot be null (clear means remove the key). Every running/month/period total must remain a safe integer, in both tentative comparisons. A legal-sized extreme plan can still exceed arithmetic/body bounds and must be rejected.
- Dates are exact YYYY-MM within 2000–2100. Windows are inclusive 1–120 months. Every generated occurrence must fit the window; schedule end need not itself be an occurrence. Once uses anchor=end and everyMonths=1; monthly/yearly are interval 1/12.
- History is sorted, unique effective occurrence months. Latest change at/before an occurrence sets its estimate; existing later points continue to apply. The original base estimate and all actuals are preserved when adding/replacing a point.
- Actuals and history must belong to scheduled occurrences. Unsupported fields are not guaranteed roundtrip; original v1 raw bytes/export remain the recovery source. IDs remain stable, including unusual text values; they are not used as object/prototype keys.
- No server revision, sessions, passphrase, filenames or access settings in exports.

## Storage / API

The private directory contains `plan.json` and a live-process `writer.lock`. Successful saves remove their temporary `.save-*` file by rename. A crash can leave an orphan temporary file and a stale lock; neither is automatically imported/deleted.

Stored envelope: `{schemaVersion:"money-seasons-store/v1", revision:positiveSafeInteger, plan:v2}`. Missing file at first startup is uninitialized revision 0/plan null, not a saved demo. Corruption/unsafe modes/symlinks/hard-link aliases block startup/edits; missing data after initialization is an error, not a reset.

Inside the single-process queue: reread/validate current envelope → compare expectedRevision → validate candidate and totals → exclusive same-directory temporary file `0600` → write/fsync file → atomic rename → fsync directory → acknowledge next monotonic revision. Finance reads wait for pending saves. After a possible rename failure, reads include `durabilityUncertain:true` and further writes are blocked until operator restart/recovery. Startup validates the file and syncs the directory before serving. The lock is never stolen, even when its recorded PID appears stale.

| Route | Boundary / behavior |
|---|---|
| POST `/api/login` | Exact allowed Host/Origin and JSON; bounded passphrase; no finance response |
| GET `/api/session` | Session required; returns CSRF token for that in-memory session |
| POST `/api/logout` | Session, same origin and CSRF; invalidate session and clear cookie |
| GET `/api/plan` | Session; envelope/current revision (or uninitialized null) |
| PUT `/api/plan` | Session/origin/CSRF; raw ≤1,000,000 bytes; `{expectedRevision,plan,operation:"edit"|"replace",confirmed:true}`; initialization/replacement must use confirmed replace |
| GET `/api/export` | Session; plan-only JSON attachment |

Errors: 400 invalid input/confirmation, 401 login, 403 request origin/CSRF, 409 stale revision, 413 body/plan size, 429 login limits, 503 unavailable/uncertain. Error responses never serialize payloads, exception text or private paths. Static assets have a fixed allowlist; health/HEAD/CSP/no-store protections remain. No request-controlled filesystem path.

Security limits: minimum 12-character privately configured passphrase, random per-start scrypt salt, random 256-bit tokens, hashed session lookup, HttpOnly/SameSite=Strict/Secure production cookie; absolute 24h sessions, logout/restart invalidation, ≤256 concurrent sessions. At most 5 failed/in-flight attempts/direct client per 15 minutes, 30 globally. Forwarded headers do not create new identities. Equal family edit access is not individual authorization or attribution; this is not a multi-tenant/public service or security audit.

## Operator recovery

**No recovery procedure here is an instruction to alter a running household instance without separate operator authorization.** Never commit the state, export, original, secret, or personal screenshot.

1. **Unsaved/conflicting browser:** keep the tab. Close the form (not the tab), export the unsaved candidate, then read server status. If the server has exactly that candidate and no uncertainty flag, the lost acknowledgement is reconciled. If revision is unchanged, explicit retry is offered. Otherwise export, explicitly reload, inspect and manually reapply wanted changes; no automatic merge. Existing form fields remain available after reload, but must be reviewed against current data. Further edits are disabled while a pending candidate needs reconciliation.
2. **Durability-uncertain response:** never claim unchanged data or retry blindly. The disk can contain the complete new envelope even though the save returned 503. Export the browser candidate. Operator checks storage health, stops only the identified app gracefully, preserves the private directory, and restarts with the same directory. Startup validates/syncs; log in and reread revision/plan before deciding what to reapply. If corruption persists, stop and use a known-good export; do not reset to demo.
3. **Writer lock after an unclean stop:** no automatic lock theft. Operator must identify the exact store/process/container and prove **no live or unknown writer** still uses it (container PID namespaces make the PID alone insufficient). Stop that instance and preserve the whole private directory first. Only after explicit recovery authorization may the operator remove that store's stale `writer.lock` and obsolete `.save-*` files; never do broad process kills or delete another store's lock. Restart one writer. This conservative availability tradeoff prevents overlapping writers.
4. **Corrupt/unsafe file:** app refuses rather than overwriting it. Stop the identified process; preserve the original bytes privately. Correct ownership/modes/symlink misconfiguration without weakening permissions. For actual corruption, restore a verified complete store envelope offline, or explicitly quarantine the corrupt file and start a new empty store, then import a known-good supported plan export with confirmation. Do not import a store envelope as a plan or silently reuse its opening date. Recheck all periods/actuals and keep the original until accepted.
5. **Disk/laptop loss:** no automatic recovery guarantee. Only a separately retained manual export/backup can restore the plan. JSON and passphrase files are not encrypted by this app. Backup scheduling/off-machine replication are deferred.
