## Using Rõ chi

- The month selector and previous/next buttons precede summaries. The default list contains only real occurrences in that month, including tentative rows. The comparison checkbox controls their contribution to totals, not whether their rows exist.
- **Xem tất cả lịch đã lưu** exposes past/future/inactive schedules for editing; totals still concern only the selected month. Search filters name/details, not summaries.
- Three shared grouping slots choose **Đối tượng / người**, a tag key, or blank. Defaults: Object / blank / blank. Skip blanks, prevent duplicate dimensions, and always split **Lặp lại / Một lần** inside the active dimensions. Missing selected-key assignments use virtual **Khác**, separately within each parent branch; no automatic assignment or double counting.
- Object identity, type icons and shared Income links remain intact. The default Object view keeps empty objects. A Category-type object is not the **Danh mục** tag key.
- Native **Ẩn/Hiện số tiền cụ thể** switches synchronize the page and every expense editor, initially off. Only monetary nodes/inputs/effective-amount details hide; common labels, actions, counts and non-money fields are unchanged. Hiding retains and validates draft amounts, including invalid text. The submit label is always **Lưu chi phí**.
- Once shows one month, with no end/frequency/N controls. Repeat reveals end/frequency; only custom frequency reveals N (integer 1–120). Monthly is 1, yearly 12. Switching fields does not erase draft inputs; saving cannot orphan estimate-history points.
- Month, grouping, search, all-schedules, disclosures and visibility are ephemeral: zero plan PUTs/revision/export changes, default settings on full reload. Visibility is **not access control**; other workspaces and exports still contain money.

## Tags and atomic editing

A new expense has **zero tag rows**, including a contextual Add inside a tag group. Contextual Add inherits only object/type. **Thêm thẻ** adds a removable row: select an existing key or create one, then select an existing value or add one. Editing shows assigned rows only. Multiple distinct keys are allowed, one value per key. Incomplete/duplicate rows must be completed or removed.

Names are NFC-normalized and trimmed, 1–40 Unicode code points, case-insensitively unique among keys or within a key's values. **Khác** is reserved for the missing-assignment fallback. IDs remain stable on rename. **Quản lý thẻ** creates/renames definitions; deletion is blocked while any expense references the key/value. Unassigning does not delete shared definitions.

New definitions in an expense form stay local to that draft. Cancel, remove, invalid input, declined confirmation or a rejected CAS save never partially updates the saved library. A valid expense and its definitions use one existing whole-plan CAS transaction. A stale 409 retains the complete unsaved candidate for export/manual recovery; it does not auto-merge or overwrite the acknowledged server plan.

Absent-only starter library:

- **Danh mục:** Ăn uống; Vui chơi; Học tập; Du lịch / về quê; Hiếu hỷ; Nhà cửa; **Quần áo**; Chăm sóc sức khỏe; Từ thiện; Đầu tư; Bảo vệ tài chính; Trả nợ.
- **Mức cần thiết:** Thiết yếu; Tùy chọn.

These are editable labels, not accounting features. An explicit empty or edited library is never reseeded. Loading/viewing an old plan shows starters in memory without adding fields, assigning tags, saving or changing forecasts. Definitions materialize only through explicit tag/expense saves.

## Optional v3 data contract

```json
{
  "tagDefinitions": [
    { "id": "key-id", "name": "Danh mục", "values": [{ "id": "value-id", "name": "Ăn uống" }] }
  ]
}
```

An expense may contain `"tags": [{"keyId":"key-id","valueId":"value-id"}]`. These are optional additions, not a version bump. Income does not accept tags. IDs share the plan-wide namespace. Malformed/extra fields, duplicate identities/names/assignments and dangling/cross-key references reject, never strip. Existing 500-item/object, forecast-window, exact-VND and 1,000,000-byte limits remain; libraries also cap keys/values per key at 500.

`public/expense-tags.js` supplies pure library/validation/grouping helpers; `public/model.js` uses shared validation for browser and server. `server.mjs` explicitly serves the helper with existing JS MIME/CSP/no-store headers. Existing persistence needs no schema/storage rewrite. Save/restart/export/import retains definitions, assignments and every old field. Untagged v3 and explicit v1/v2 original-preservation/conversion gates remain supported.

**Rollback caution:** pre-MS-004 strict v3 readers reject these optional fields instead of silently discarding them. Export privately first and retain a tag-aware build or a separately retained pre-tag export. Do not remove tag fields from financial JSON to force an older build to accept it.
